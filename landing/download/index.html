BEFORE YOU START

A little preparation.

  • 64-bit Windows 10/11.
  • Setup prepares supported Python and missing Microsoft runtime dependencies.
  • A writable installation folder.
  • Internet to download missing Python, components or model weights.
  • Available storage and memory for your chosen model.

The current ZIP is not a fully self-contained offline installer. A prepared installation reuses its components without a package download; completing welcome setup does not require internet. Existing 64-bit Python 3.10–3.14 installations are supported. If needed, setup installs Python 3.14 through Windows Package Manager and requests Microsoft’s signed x64 runtime installer. An optional local AI issue does not block the welcome page; the launcher keeps repair details available. If setup needs help, use Open logs in the launcher or TLI_Diagnostics.bat.

01 / BEFORE YOU START

Check your Mac.

The bundled runtime requires macOS 14+ on Apple Silicon or macOS 13.3+ on Intel. Install standard Python 3.13. Final CPython 3.10–3.14 builds without free-threading are supported; Python 3.15 and prerelease builds are not. The Intel package uses a hash-verified prebuilt encryption component, so setup does not require Rust or OpenSSL build tools. For a python.org installation, also run Install Certificates.command in its Python folder under Applications. Downloading missing Python or required components needs internet access. Once those components are installed, you can complete the welcome offline. This ZIP does not include every prerequisite or model weight.

Mac setup failed at cryptography or Python?+

Install standard Python 3.13, fully quit TLI, and keep your original TLI folder. Installing Python does not replace an existing backend/.venv. Follow the Mac Python recovery steps to preserve the old environment, prepare a supported one if needed, and apply the current update. Keep saved data, models and Vault files intact; do not start a second copy from the update folder.

Mac says “TLI_Start.command” Not Opened+

The current ZIP uses an unsigned Terminal launcher. macOS may block it before setup can run. If you downloaded this official TLI release and trust it:

  1. Click Done on the warning.
  2. Open Apple menu → System Settings → Privacy & Security.
  3. Scroll to Security and find the blocked TLI_Start.command entry.
  4. Click Open Anyway, then confirm Open. Authenticate if asked.
  5. Continue setup in Terminal. Keep the window open until startup completes.

If the entry is missing, try opening the launcher once more, then return to Privacy & Security. Managed Macs may require an administrator. This approves that launcher without disabling Gatekeeper for other software. Read Apple’s instructions.

If the warning says the file will damage your computer, was moved to Trash as malware, or is damaged, stop and report the exact warning instead of following these approval steps.

Which features am I downloading?+

Both desktop downloads are TLI 1.4.8-beta, released October 22, 2026. Ask TLI supports writing, learning, planning and coding conversations. Add selected documents or saved notes when useful. Connected tools include LAN Messages and approved file sharing, computer-help reports and saved steps, supported Shelly controls, reviewed manual routines, Files, the Free Space map, a passphrase-protected encrypted Vault, and Builder for small HTML/CSS/JavaScript apps.

The local AI engine is included. Model weights are not included; existing compatible models can be reused. Free Space lets you review exact files before moving them to Trash. Moving a file to Trash may leave its bytes on the same drive. Website examples use illustrative data and example responses.

See the 1.4.8-beta release notes. The separate Android Companion beta needs its own app and a compatible, configured host. Neither desktop ZIP includes a phone app. Download Android Companion above without email verification.

Can I chat and share files around my home?+

Use LAN Messages to send text between trusted TLI computers on your local network. Both computers need TLI running, a reviewed secure connection and permission to exchange messages. A delivery acknowledgement means the other computer recorded the message, not that a person read it.

For file sharing, the recipient reviews and accepts each incoming file before its contents transfer. Verified files arrive in the encrypted TLI Inbox for deliberate download. This is individual file sharing, not automatic folder synchronization.

How does computer help work?+

Describe a problem, review an available check for the chosen computer, and save its report with the steps you tried. Ask TLI about the selected evidence, record what happened, and reopen the investigation if the problem returns.

Reports show what was observed and when. A completed check does not prove a cause or a repair. Remote checks need separate permission, and the lightweight inference Node supplies AI compute only.

Which Shelly devices can I use?+

TLI supports local on/off control and reported state for compatible Shelly Gen2/Plus switch and relay devices. Power readings are available when the device reports them. Add the device on your local network, name it, then use its controls or a direct request such as “Turn on Office Lamp.” TLI checks reported state after a command and tells you when the result cannot be confirmed.

Support depends on the model and its local interface. Shelly Gen1 and devices requiring Shelly device authentication are not supported by this integration. Check your model's compatibility before connecting it. Routines are reviewed sequences you run manually; automatic schedules are not enabled in this release.

What can TLI read from documents and images?+

Choose supported text files or review extracted text from a PDF or DOCX before sending your question. TLI shows extraction coverage and may send selected excerpts to fit your model. PDF/DOCX extraction does not include OCR or preserve the original page layout. Image-only or protected documents may not yield usable text.

Questions about shared images and screenshots require a compatible vision model. A screenshot is the snapshot you attach; TLI does not continuously watch your screen. Review AI answers and cited passages against the original source.

What does Builder create?+

Describe a small browser app, generate HTML/CSS/JavaScript, try the isolated preview, ask for improvements, and download a saved version as a ZIP. Earlier revisions remain available. Generated apps use in-memory state that resets on reload; Builder projects and revisions are saved on your TLI host.

Builder does not install packages or run generated servers. Try the behavior yourself and review the source. Its browser smoke checks are advisory, and generated code can need several revisions.

Do I need an AI model?+

You can finish welcome setup and explore the workspace without a model. AI-generated answers require a configured model: reuse a compatible model already on this computer or a supported local provider such as LM Studio. The local AI engine is included; model weights can be downloaded separately when needed. Choose a model appropriate for your computer; download size, memory needs, and response speed vary by model and hardware.

Does everything run offline?+

You can complete welcome setup offline once TLI’s required components are installed. Local conversation also works offline with a compatible local model and runtime or a configured local provider. Existing models can be reused; a new model download is optional. The current ZIP is not a fully self-contained offline installer: downloading missing Python, components or model weights requires internet access. Optional online services, including internet search and cloud providers, also need connectivity and receive the relevant requests you send.

Supported local Shelly controls need the host and device on a working local network. You can explicitly select a trusted LAN computer for supported text inference after configuring trust and permission. The primary TLI host remains necessary, and an unavailable model does not automatically switch the request to another computer.

Windows setup stopped or Python was not found.+

Make sure the ZIP is fully extracted into a writable folder. If setup reports a missing component, internet access is needed to download it. If automatic Python installation fails, install 64-bit Python 3.14, then open TLI.exe again.

Run TLI_Diagnostics.bat from the extracted folder for visible setup output. If setup still fails, email the error text to thelanintelligence@gmail.com.

My browser opens the wrong page, or will not connect.+

Wait for setup to finish; on Mac, keep the Terminal window open until startup completes. Use the address shown by the launcher, normally http://localhost:8000 on the same computer. Another server or older TLI may already use port 8000. Stop the old TLI through its own controls, or close the other server you recognize, before starting this installation.

If the page still will not load, check the launcher output for errors and include them when requesting help.

Already using TLI? Keep your setup when you update.+

1.4.6 or newer: open Settings → Software Updates → Check for updates. Choose Download update, then Install and restart. Review the version and original host address, finish active work, and confirm. TLI verifies the restarted host before offering Reload TLI.

1.4.5: the app first offers the 1.4.6 updater migration. Download it inside TLI, open the prepared folder, quit the original host, then run TLI_Update.bat on Windows or TLI_Update.command on Mac from that new package. Select your original folder and confirm. Reopen the original installation and check again: the full 1.4.8 update can finish inside TLI.

Older versions or a failed download: download the matching current ZIP from the official GitHub release without registering again. Extract it separately, stop the old host and use the new package TLI_Update launcher against your original folder. Do not start a second copy or move your saved data into a staging folder.

Data, identity, PIN settings, models and the Python environment stay with the original installation. Keep separate backups of important saved data and Vault content. Internet may be needed for changed Python dependencies. Use the normal local desktop launcher; remote browsers, phones, diagnostic hosts and old frozen backends cannot install updates. Close any separate launcher or optional Host Start helper if the review reports it.

Read docs/TLI_UPDATES.md in the ZIP for manual recovery and rollback. The desktop updater does not install the separately distributed Android Companion. Automatic checks do not download, install or restart by themselves.

How do I uninstall TLI?+

Windows: after setup, use TLI’s entry in Settings → Apps → Installed apps, Uninstall TLI in Start, or Uninstall_TLI.bat inside the installation you want to remove. Review its full folder path and stop that installation’s host, launcher and optional helper first. You can remove Windows entries while keeping every file, or choose complete removal. Complete removal permanently deletes that folder, including saved data, Vault and models stored there, and requires typing DELETE. Back up anything needed outside that folder first.

macOS: Uninstall_TLI.command provides manual removal guidance. Use Quit TLI inside the app, back up anything needed outside the installation, and move only its extracted folder to Trash. The helper does not automatically stop programs or delete files.

Read docs/TLI_UNINSTALL.md inside your ZIP. Other TLI copies, shared software and files saved outside the selected installation are separate.

Use the GitHub releases page for published release notes and package assets. Choose TLI_1.4.8-beta_Windows.zip or TLI_1.4.8-beta_macOS.zip for your platform. GitHub's “Source code” archives are a different download and are not the package described here.
