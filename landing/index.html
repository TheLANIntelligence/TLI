BETWEEN YOUR COMPUTERS

Send it across the house.

Use LAN Messages to chat between trusted TLI hosts on your home network. Offer a file, let the receiver approve it, and collect the completed transfer from the encrypted TLI Inbox.

Both hosts must be available, with their identities reviewed and messaging allowed. Delivery is not a read receipt; downloading an accepted file is a separate step.

SHELLY DEVICE CONTROL

Your lamp, by name.

Discover and configure compatible Shelly Gen2/Plus switches and relays. Ask “Turn on Office Lamp” or “Check Office Lamp.” See the command acknowledgement and the device’s subsequently reported switch state.

Power readings appear when the device supplies them. A reported switch state does not prove the connected appliance is working. See compatibility details ↗

REVIEWED MANUAL ROUTINES

Keep familiar steps together.

Save a supported sequence of device actions as a routine. Review its targets and steps, then choose when to run it.

Saving a routine does not run it. Scheduled, presence-based, and other automatic triggers are not active.

BEFORE YOU CONNECT

What works,
and what it needs.

Which Shelly devices can I connect?+

The current adapter targets compatible Shelly Gen2/Plus switches and relays with a locally accessible Gen2 RPC switch interface. It supports On, Off, Toggle, and reported status. Power readings depend on the device. Discovery searches the host’s local IPv4 subnet.

Gen1 devices and device-password authentication are not supported by this adapter. Compatibility depends on the device and configuration; the beta is not a certification of every Shelly model.

What about other smart devices?+

TLI also includes adapters for these configurations. They need individual setup; discovery and model support are not universal.

  • Philips Hue with a configured Bridge and API key; Govee and Yeelight with supported LAN control enabled.
  • WLED’s local API, Sonoff in supported DIY mode, and older Kasa devices using the legacy protocol. Newer Kasa KLAP/Matter models are not supported by that adapter.
  • Tuya Local with the optional tinytuya dependency, device ID, and local key; generic HTTP devices with configured request URLs.

An optional, temporary Home Assistant connection can read reported light and switch states and submit individual, reviewed On/Off actions. Home Assistant must already be configured. This connection does not add its devices to AI chat or enable its scenes and automations.

How does in-home chat and file sharing work?+

Run TLI on both computers on your LAN. Review each computer’s identity and secure connection, and allow messaging before exchanging messages. File offers also need the receiver’s approval. A completed transfer is stored in the receiving host’s encrypted TLI Inbox, ready for a separate download.

This is messaging between configured TLI hosts, not a connection to third-party messaging accounts. A sent or delivered message does not establish that someone has read it.

Can TLI use AI on another computer?+

Yes. Review the other computer and its inference permission, then explicitly choose an available model there for supported text requests. Your main TLI host retains the conversation; the selected computer processes the request it receives.

Both hosts and the model must be available. TLI does not silently switch to another LAN model if that connection fails.

A FEW THINGS TO KNOW

Your questions.
Straight answers.

Visit the install guide ↗
Is the new experience available to download?+

Yes. TLI 1.4.4-beta brings the current desktop workspace to Windows and macOS: Ask TLI, appearance themes, Files, Vault, reviewed LAN connections, and small-app Builder. This page uses illustrative data and curated demonstrations. Your installation starts with your own setup.

Can TLI work without the internet?+

Yes. Once TLI’s required components are installed, you can complete the welcome, choose a theme and optional PIN, and explore your workspace offline. Reuse a compatible model already on your computer or a configured local provider for AI conversation. The current ZIP is not a fully self-contained offline installer: downloading missing Python, components or model weights needs internet access, as do optional online services. Your LAN is still needed for connected computers and local devices.

What hardware do I need?+

Requirements and response speed depend on your model, available memory, and CPU or GPU. Start with a model that fits your computer. Windows 10/11 needs 64-bit Python 3.10–3.14 (3.14 recommended); the launcher can install Python 3.14 when needed. The bundled Mac runtime needs macOS 14+ on Apple Silicon or 13.3+ on Intel. See the install guide for setup details.

Where does my data go?+

TLI keeps its saved work on the host. Local inference processes requests on your own hardware. Choosing a LAN model shares the relevant request with that trusted computer. Optional external providers and services have their own data paths; choose them deliberately.

Does it control everything automatically?+

No. Supported devices need configuration, computers need appropriate trust, and file organization, cleanup, and manual routines have their own review steps. TLI distinguishes a command acknowledgement from a checked outcome. AI answers and generated apps still need your judgment.

Can I use TLI on my phone?+

The separate Android Companion beta connects to a compatible, configured TLI host. A phone app is not included in these desktop ZIPs, and this website does not offer a phone download, an iPhone app, or built-in off-LAN access.
