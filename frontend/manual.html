TheLANIntelligence

TLI is your private home console for computers, devices, files and local AI. The computer hosting TLI stores your saved information. Optional online search, downloads, registries and configured external services make network requests; their settings explain where they connect. Features depend on the host's platform, available providers and license.

Quick Start Guide

Set up protected access, then choose an available AI option.

  • Run install.bat Extract the TLI zip, double-click install.bat. It copies files, sets up auto-start, and creates a Desktop shortcut.
  • Open TLI in your browser Use the Desktop shortcut or go to http://localhost:8000. TLI opens in your default browser — no app required.
  • Complete the setup wizard Name your node (e.g. "Home Server"), set an optional access PIN, and continue. Takes about 60 seconds.
  • Download an AI model Open the model library and review compatibility on the computer hosting TLI. Downloading installs model files; selecting and starting a model are separate operations.
  • Start chatting Wait for confirmed runtime readiness after selecting a compatible installed model. Type a question and review its context before sending.
  • Access from other devices On any device on your home network, open a browser and go to http://your-pc-ip:8000. No install needed on those devices.

Find your PC's IP: Open a terminal and run ipconfig. Look for the IPv4 address under your active adapter (usually 192.168.x.x). Alternatively, TLI's Mesh panel shows your node address automatically.

What is TLI?

TLI gives you a unified control panel for your entire local environment. It replaces a dozen separate tools with one browser-based console that knows your network, your devices, your files, and your secrets.

TLI's bundled AI and local features can work without internet access after installation. Downloads, updates, online search and external providers use their configured connections when enabled.

Installation

TLI is distributed as a ZIP package. There is no traditional installer wizard — just a batch file that sets everything up.

Requirements

  • Windows 10 or 11 (64-bit)
  • ~200 MB disk space for TLI itself
  • ~1–5 GB additional disk space for the AI model (downloaded separately after install)
  • Any modern browser (Chrome, Edge, Firefox) — no special browser required

Install Steps

  1. Download TLI_dist_0.9.9.8.zip and extract it anywhere (e.g. your Desktop or Downloads folder).
  2. Open the extracted folder and double-click install.bat. No admin rights required.
  3. The installer copies TLI to %AppData%\Local\TheLANIntelligence\, registers it to auto-start on login, and creates a Desktop shortcut.
  4. Your browser opens automatically to http://localhost:8000. Complete the setup wizard.

Auto-start: After install, TLI's backend starts automatically every time you log into Windows. You don't need to do anything — just open your browser and go to localhost:8000.

Uninstalling

Run uninstall.bat from the install directory (%AppData%\Local\TheLANIntelligence\). This removes the backend, startup task, and Desktop shortcut. Your vault data and settings in the data\ subfolder are preserved — delete that folder manually if you want a complete wipe.

Accessing TLI from Other Devices

TLI runs on your machine and is accessible to any device on your home network. No install is needed on those devices.

  1. Find your PC's IP address: open a terminal and run ipconfig. The IPv4 address looks like 192.168.1.x.
  2. On any other device (phone, laptop, tablet), open a browser and go to http://192.168.1.x:8000.
  3. TLI loads in that browser. It's your TLI instance — same vault, same AI, same everything.

If the other device can't connect, check that your Windows Firewall allows port 8000. TLI attempts to add this rule automatically at startup, but you may need to approve it.

First-Run Setup

On first launch, TLI walks you through a short setup wizard:

  1. Node Name — Give this TLI instance a name (e.g. "Gaming PC", "Home Server", "Office"). This name appears in the mesh directory when other TLI nodes discover yours.
  2. Access PIN — Set a 4–32 character PIN to lock TLI. Recommended if others share your network. You can skip this and set it later in Settings.
  3. AI Setup — TLI checks whether a local AI model is installed. If none is found, you'll see a prompt to download Qwen2.5. Pick a preset (see below) and click Download — it runs in the background. If storage or hardware is a concern, you can skip this step and use a mesh node's AI instead — see AI Providers.
  4. Done — The wizard marks setup complete. TLI lands on the Dashboard.

Dashboard

Start with what needs attention, the Narrator, compact observed health and activity catch-up. Host availability, AI readiness and system health are separate. Read the computer or drive named in an alert before acting.

CPU, RAM and disk observations become stale after 30 seconds without a successful probe. Unknown values are not zero. Sustained CPU/RAM warnings use their existing timing; critical disk warnings can appear immediately. The full activity feed remains available even when the Narrator suppresses repeated messages.

Use Make the next move to open existing tools. More shortcuts includes Notes & fixes and Phone Companion. Opening Free Space does not free space. Activity is marked reviewed only through its explicit review control; historical warnings are not fresh checks.

AI Chat

Ask a question and watch the response indicator while TLI works. Review the provider badge and context summary before sending. The connected host, an explicitly selected computer, a diagnostic report, documents, notes and images have distinct sharing rules.

Existing status, navigation and supported device commands can use deterministic handlers. General AI answers require an available provider. An answer can be wrong even when inference is healthy; inspect its supplied context and any action receipt.

Notes and conversation context

Use saved notes allows ordinary chat to include relevant Notes & fixes when enabled. Disabling it does not remove earlier conversation messages. New Chat starts a separate conversation. History resumes a saved conversation without automatically sending a message.

Earlier conversation starts on for each ordinary question. Turn it off in the context summary to leave prior messages out of that request without deleting the conversation. Selected-note and document questions retain their stricter standalone sharing rules. The latest question and explicitly selected computer guide the request; a conflicting report must be reviewed before sending.

Evidence for this answer identifies observations, saved information and included sources from the actual request. The model's explanation is interpretation. A dated saved report or historical fix does not establish current health. Source references are checked against supplied handles and document lines; an unknown reference remains unverified. A matched reference identifies a source, not proof that the model's claim is correct.

A short follow-up such as “What fixed it last time?” can refer to the recent user question in this conversation. TLI still checks the current saved note version and the explicitly selected computer. This is limited word-based recall; an unrelated new topic or another conversation does not silently supply a subject.

Save to Notes & fixes… lets you save a reviewed reply as a new note or deliberately update an existing note. Review its current and proposed text before saving. If another view changed the note, review that newer version first. Replacing a confirmed historical fix with an AI suggestion does not confirm the new advice.

Documents: select up to four UTF-8 .txt or .md files, with a combined limit of 64 KiB. Longer documents use whole numbered lines chosen for your question or sampled across the text. The answer’s document details show the included lines and omitted coverage. Original files stay unchanged. Citations are generated by the model and can be wrong; omitted passages may contain important exceptions. Document questions exclude earlier conversation and other context.

PDF and DOCX: choose Check PDF & Word support first. Extraction requires HTTPS or localhost and an available bounded reader. Selecting a supported file up to 8 MiB uploads the binary to this TLI host before Send; inspect and accept the extracted text before adding it to the question. Extraction reports omitted content; it does not perform OCR or execute macros. Existing document-count, text and model-input limits still apply. An extraction preview is not an automatic attachment.

Local voice: open the voice dialog, check on-device recognition support and explicitly start recording. Review the editable transcript, then choose Add to draft. Recording does not send the question. Playback offers only voices the browser reports as local. Unsupported local speech remains unavailable; language-pack installation is a separate explicit choice.

Response timing measures what this browser sees: waiting for the first text and elapsed response time. It is not a measure of model reasoning. Stop ends receipt in this view; it cannot guarantee that a server action stopped. An interrupted reply remains incomplete, and retry requires another deliberate Send.

Questions about up to four selected notes stand alone: the selected note versions and current question are supplied, without earlier conversation, documents, images, other saved memory, tools or selected-computer/report context. Remove displayed conflicts before sending. Bundled and configured LM Studio support this path; unsupported mesh routing does not silently receive it.

Vault content remains separate. Unlocking Vault does not share it with AI. Copying a secret into a question or deliberately using a supported secret reference can expose it to the provider and saved conversation.

Notes & fixes and conversations follow the current TLI account. With PIN protection disabled, local access shares one owner.

Notes & fixes

Keep setup details, preferences and past fixes so you can refer to them later. Setup detail, Preference and Fix to remember open unsaved drafts. Save explicitly; choosing the fix starter does not mark a fix confirmed.

User notes, saved AI replies and confirmed historical fixes have distinct source labels. Back, Close and opening another note retain unfinished drafts in memory; discard is explicit and locking clears drafts. Vault notes remain behind their separate passphrase.

Linked notes records a reviewed relationship to another note's exact revision. Changed or missing sources stay visible; a correction reference is not proof that a fact is correct. Related notes separately reviews selected notes before using an existing local embedding server to build a temporary search index. Similarity results are suggestions, and do not silently change Chat's memory or attach notes.

Phone Companion

Open Home & network → Phone Companion. Settings, Computers, onboarding and Ctrl+K lead to the same page. Opening it does not create an invitation.

  1. Owner access: install a supported native Companion build, set an owner PIN through the linked Settings controls, and unlock TLI.
  2. Secure connection: use HTTPS, LAN access and an address covered by the host certificate. Review running, saved and effective next startup settings. A saved change requires a manual restart when indicated.
  3. Pair your phone: choose Create pairing QR, then scan it in the native app or use the manual bundle. The invitation is single-use and expires after five minutes. Hiding it does not revoke it.
  4. Manage paired phones: check observation times and explicitly remove access when needed. A failed refresh preserves previous entries; an unavailable list is not empty.

The older Browser satellite code connects a browser and is not a native pairing QR. This browser update does not install, rebuild or pair the native app for you.

Beyond home Wi-Fi: an externally managed private route can make the already paired private HTTPS address reachable. TLI does not create a VPN or open public ports. Keep the existing certificate and pairing; a listed address does not prove that the route works. Reconnection never automatically replays Chat or actions.

Vault

Vault keeps personal files, secret values and private note contents encrypted on the computer hosting TLI. A separate Vault passphrase opens them; your access PIN controls entry to TLI. Vault notes are separate from Notes & fixes and AI conversation history.

File names and note titles remain visible in stored filenames. Secret names and values are inside their encrypted store. When connecting from another device, the passphrase is processed by the TLI host. Use a secure HTTPS connection for that access.

Initial Setup

  1. Choose Set up Vault to open Security settings. Choose and confirm a long, unique passphrase; the minimum is eight characters.
  2. Keep the passphrase somewhere you can recover it. Spaces and capitalization are part of the passphrase.
  3. After setup, open Vault and enter the same passphrase to unlock it.

Access and Locking

Access lasts 30 minutes from a successful unlock. Reading or editing does not extend that time. Unlocking applies to this TLI account, including its other signed-in sessions. Closing a tab does not lock Vault, and unexpired access may survive a host restart.

Choose Lock Vault to end access for the account. Save your notes first; unsaved edits are discarded when you confirm locking. If TLI cannot confirm removal of a saved unlock session, private content is hidden and an error explains the remaining risk. Retry locking explicitly.

Ten wrong passphrases cause a ten-minute lockout. Passphrase help explains the available options; it cannot reveal or recover the passphrase.

Files

Open Add a file, choose a file, then select Encrypt & add file. The original file stays where it is. Search by stored name or sort by encrypted size. Names are normalized for storage; review a matching name before replacing an existing file. Files beginning with two underscores are reserved for internal Vault data.

Download saves an ordinary, unencrypted copy through your browser. Locking Vault does not remove downloaded copies. Delete permanently removes the Vault copy after confirmation. Individual uploads are limited to 250 MiB.

Secrets

Use Add a secret to enter a name and value, then choose Save secret. Search names and deliberately choose Show or Copy when you need a value. Copied values remain in your device’s clipboard; hiding a value or locking Vault does not erase the clipboard.

Vault Notes

Choose New note, enter a title and text, then choose Save note. You can search existing titles and reopen a note to edit it. Typing does not save automatically. Changing a title saves under the new title; the original note remains. A matching title may replace an existing note after review.

These notes stay in Vault. They are not the setup details, preferences and past fixes stored in TLI’s separate Notes & fixes view.

Existing Login Data

Legacy saved-login data is preserved, but this Vault interface does not expose Logins or Extension tabs. See legacy extension status. Saved logins are excluded from the encrypted-file export below.

Encrypted Copy and Reset

  • Download encrypted copy includes encrypted files, Vault notes and this account’s secret store. It omits saved logins, Vault metadata, encryption salts, machine keys and sessions.
  • This ZIP is not a standalone, restorable backup. Keep the matching original installation and Vault metadata as well as the passphrase. The passphrase alone cannot reconstruct the encryption key without the original salt. There is no archive import or Restore button.
  • Delete Vault data & reset requires the correct current passphrase and RESET VAULT. It permanently deletes Vault files, secrets, saved logins and Vault notes. Reset does not recover a forgotten passphrase.

TLI cannot recover a forgotten Vault passphrase. Keep your original data and matching installation if you may remember it later. If Vault reports unavailable or damaged saved data, do not run setup over it. Existing files are preserved when a read or save fails.

Choose a routine starter, prepare up to 20 supported steps and preview every exact device and relay before saving. Saving runs nothing. Open a saved routine, review its current targets and explicitly choose Run. All targets must resolve before any step executes; duplicate requests do not start another run. Inspect per-step results and saved receipts for failure, partial completion or an uncertain result.

Legacy trigger, enabled and cooldown fields remain preserved. This installation has no active presence, power or scheduled-trigger executor; these fields do not activate automatic work.

Optional Home Assistant

Smart devices offers a temporary connection to an existing Home Assistant server. With the owner PIN unlocked, review its origin and private addresses before entering a token. Files & Free Space

Files: choose → prepare → review → results

Choose an accessible folder on the TLI host. Prepare organize or rename changes, review exact paths and collisions, then explicitly run the reviewed operation. Results can be partial; inspect them before retrying. Undo only covers its recorded operation and checks for later changes.

AI suggestions are written advice. They do not create or approve an operation plan. A category groups scan results; opening Free Space from that group prepares the folder. Choose Scan there to inspect it. Previous advice and previews remain when replacement work fails.

Free Space: scan, compare and cleanup review

Choose a drive, quick folder or exact path on the TLI host, then choose Scan. Quick overview inspects for up to 15 seconds; Deeper scan can run for up to five minutes. Both have entry, depth and resource limits. Follow real progress and coverage, then inspect the largest files, folder totals, File types or Map. The list views provide a keyboard-accessible alternative to the map.

Stop scan requests cancellation; leaving the page does not. Failed replacements preserve previous results and their observation time. Permission failures and scan limits remain visible. Large-file search, Duplicate search, Common folders and Saved comparisons start only when requested. A saved comparison is not a fresh check of the drive.

Select individual files for an exact-path cleanup review. Moving reviewed files to Trash is explicit; file sizes do not prove how much space was freed because Trash may still occupy storage. If an outcome is uncertain, check its existing receipt instead of sending the move again. Prepare a question about a scan reviews what will be shared and does not send Chat automatically.

Printers & USB

Refresh printers reads the host inventory. Printer settings opens the host operating system's settings. Open scanner app opens its scanning application. Send test page explicitly submits a job; it does not confirm that paper printed. Missing supply, queue or device information remains unknown.

Print & Scan

Choose a printer or scanner available on the host and the document or scan options. Selecting a printer from inventory opens Print & Scan after its selection handoff completes. A completed scan provides a downloadable file. A failed replacement retains the previous download until a new scan is successfully retrieved.

Supported operations depend on host OS facilities, installed drivers and the device. A browser on another computer controls the TLI host's workflow, not that browser device's printer.

Performance & apps

Choose a running process on the computer hosting TLI, describe the symptom, then explicitly start a 30-second observation. The process ID and creation time bind that selection to one launch; a process may represent only part of an application. Exiting or reusing the process ID never silently retargets the observation.

Review CPU and memory readings with their duration, valid samples and missing fields. Stop produces a partial result. Failed replacement work retains the previous result. These observations do not measure FPS, dropped frames, GPU load or thermal throttling and do not prove a causal bottleneck.

Save a useful observation explicitly to diagnostic history. You can then review a Chat handoff or add its report link to Troubleshooting. Comparing saved observations includes host and workload caveats; application differences require matching host and known executable identity. Opening a report never runs another observation.

The secondary gaming controls retain hardware and settings readers for Cyberpunk 2077, The Witcher 3 and Red Dead Redemption 2. Read settings for the selected game, describe your goal and explicitly request advice. Desired FPS is a goal, not a measured result. Stop identifies interrupted advice; failures retain the previous answer. No settings are applied and no process is terminated.

Troubleshooting workspace

Follow a problem through Describe → Choose computer → Review a check → Run → Review evidence → Record what helped. Opening a case, choosing a symptom or reviewing a suggested check does not run a diagnostic or send a Chat request.

Review the executing host, measured target, scope and any internet contact before Run. System and network checks measure the TLI host. A device check measures reachability from that host; it is not a remote CPU or application test. Unavailable capabilities remain unavailable.

A completed check saves a diagnostic report. Reviewing its link, adding it to a problem draft and saving the problem are separate actions. If a problem save fails, the report and draft remain available and the check is not repeated. A conflict requires deliberate review. Marking a problem Resolved records your conclusion; saving a confirmed historical fix is another explicit action.

Continue with TLI reviews the case revision, selected steps and evidence before asking Chat. Reusable guides prepare editable, unsaved planned steps; they do not carry a computer, evidence or completed outcome. Guide files contain unencrypted text, so review them before export or import.

Saved reports offer an explicit review before repeating the same supported check. Compare results with their scope, coverage and observation times. Reviewed case exports let you select evidence and redactions before downloading HTML, text or JSON. These are historical, unencrypted copies, separate from encrypted saved-work backups.

LAN Discovery

Enabled discovery helps reachable TLI peers on a compatible LAN find each other. It depends on broadcast reachability and host/firewall configuration. It does not inventory every computer or grant control over unregistered devices.

If a peer is missing, check both TLI installations, displayed addresses and current network settings. Native Phone Companion pairing and Browser satellite invitations are separate from computer discovery.

Security & PIN

TLI is designed for trusted home LAN environments. It is not intended to be exposed to the public internet.

Key Security Properties

  • Local data is stored on the TLI host. Enabled online search, updates, downloads and configured external connections can send requests outside the LAN; review those settings for your setup.
  • Vault contents use AES-256-GCM with PBKDF2-SHA256 key derivation (200,000 iterations and a 16-byte encryption salt). Password verification uses a separate salt. Unexpired unlock keys may be stored encrypted with a machine-local key.
  • Sessions are cookie-based (httponly, samesite=strict). Valid for 24 hours, revoked on PIN change/removal.
  • The PIN hash is stored, never the PIN itself.
  • Notes & fixes and conversations follow the authenticated account. When PIN protection is disabled, local access shares one owner.
  • HTTPS is available through reviewed startup settings. It must be active with a usable certificate before native phone pairing; a saved choice alone does not change the current connection.
  • All API responses include security headers: X-Content-Type-Options, X-Frame-Options: DENY, Content-Security-Policy, Permissions-Policy.

Recommended Practices

  • Set an access PIN if anyone else is on your LAN or WiFi.
  • Use a long, unique Vault passphrase. Keep the matching Vault data and metadata; an encrypted-file export alone is not a complete recovery backup.
  • Do not port-forward TLI to the internet (port 8000 should not be accessible outside your home network).
  • If a legacy Vault Extension key may be exposed, lock Vault and stop using that integration until its access is reviewed. The current interface does not provide extension key-management controls.

Troubleshooting

TLI won't open after install

  • The backend may still be starting. Wait 10 seconds and refresh.
  • Check if tli_backend.exe is running in Task Manager.
  • If it crashed, navigate to %AppData%\Local\TheLANIntelligence\ and run start_tli.bat manually to see error output.

Can't access TLI from another device on the LAN

  • Confirm TLI is running on the host machine (open localhost:8000 on the host first).
  • Check that Windows Firewall isn't blocking port 8000. Allow it in: Control Panel → Windows Defender Firewall → Allow an app.
  • Make sure both devices are on the same network (same router/subnet). WiFi and wired devices on the same router are usually on the same subnet.
  • Use the machine's actual IP (ipconfig in terminal), not localhost, from the other device.

AI chat returns "No available AI provider"

  • The bundled AI may still be loading — first start can take 30–60 seconds. Wait and try again.
  • If selected model files are unavailable, open the model library to review installation and compatibility. An installed model is not necessarily running.
  • Check Settings → AI Model for runtime status and any error messages.
  • If using LM Studio, verify it's running and the URL in Settings is correct.

AI gives wrong date or seems unaware of the current time

The bundled AI is context-aware — it receives the current date, time, and node info with every message. Check the supplied context and host clock. Runtime readiness does not guarantee accurate answers; restarting is not proof that an answer will improve.

Lock screen won't dismiss / PIN not working

  • Make sure Caps Lock is off — the PIN is case-sensitive.
  • Use Forgot PIN? for recovery guidance and Recheck access status. Preserve existing files before restoring a matching backup. Windows-protected keys may require the original account and computer; do not run setup over unavailable security files.
  • Hard-refresh the browser first: Ctrl+Shift+R. A cached version of the app can sometimes get stuck.

Vault says "Vault locked" right after unlocking

Vault access expires 30 minutes after a successful unlock, and another signed-in session for the same account can lock it sooner. Choose Check status to see the current state. If TLI access itself has expired, unlock TLI first, then enter the Vault passphrase. A failed status check means availability is unknown; it does not mean your Vault is empty or needs setup.

Mesh node not appearing in directory

  • Ensure both nodes are on the same LAN subnet.
  • UDP port 47474 must not be blocked by either machine's firewall (auto-discovery uses this port).
  • Wait up to 30 seconds after the second node starts — that's the beacon interval.
  • You can also join manually: enter the other node's IP:8000 in the Mesh panel.

Duplicate node entries in Mesh panel

This can happen if TLI was reinstalled on the same machine, generating a new node ID. TLI preserves separate identities even when their names match. Inspect identity and observation time before treating a record as obsolete; a shared name alone is not a reason to remove it.

Vault Extension not autofilling

The legacy extension is not configured or verified by this release. There are no Extension or Logins tabs in the current Vault interface. See legacy integration status; do not reset Vault to troubleshoot autofill.

Games panel shows "No game detected"

The game scanner reads the foreground window process every 2.5 seconds. The game must be running and in the foreground (not minimized). For launchers that spawn indirect processes, use Add Game Manually with the full .exe path.

Scripts panel warning banner appears unexpectedly

TLI's danger scanner flags 15 patterns including disk formatting, registry deletion, and user account commands. If your legitimate script triggers a false positive, review it carefully before running — the warning is informational, not a block.
